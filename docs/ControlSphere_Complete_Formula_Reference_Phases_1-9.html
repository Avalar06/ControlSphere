Section 1: Formula Governance & Mathematical Principles

ControlSphere strictly adheres to foundational software engineering and cybersecurity governance principles governing all numerical calculations:

Core Mathematical Governance Tenets
  • Server-Authoritative Execution: No computed values (health scores, inherent risk, residual risk, coverage percentages, readiness scores, compliance indexes) are ever accepted from client payloads. All mathematical metrics are calculated exclusively server-side in Python services.
  • Deterministic Computation: Given the identical operational state (evidence timestamps, finding severities, assessment responses, crosswalk weights), the scoring engines produce 100% bitwise-identical mathematical results. No non-deterministic random variables or unanchored heuristics are employed.
  • No Stochastic / Unverifiable AI Scoring: ControlSphere strictly prohibits AI/LLM models from generating risk scores, audit readiness percentages, or compliance health values. Human reviewers issue opinions; deterministic engines calculate math.
  • Explicit Numerical Clamping: All percentage and normalized score scales are mathematically clamped to their legitimate physical boundaries: $[0.0, 100.0]$ for percentages and health scores, $[1, 25]$ for $5 imes 5$ risk matrices, and $[0.0, 1.0]$ for crosswalk confidence.
  • Standardized Decimal Rounding: All user-facing scores and percentages are rounded to 1 decimal place using standard mathematical rounding (round(val, 1)). Crosswalk confidence scores are rounded to 2 decimal places (round(val, 2)).
  • Historical Immutability: Point-in-time snapshots (such as ControlHealthSnapshot, FrameworkComplianceSnapshot, and approved VendorAssessment line items) are permanently immutable once written. Superseded records preserve historical metrics without modification.

Section 3: Phases 1–5 Core Governance & Risk Calculations

3.1 Phase 2: Framework Control Compliance Score

Located in backend/app/services/control_service.py. Evaluates the aggregate implementation maturity of a framework:

Control Compliance Score Formula
ext{ApplicableCount} = N_{ ext{total}} - N_{ ext{NOT\_APPLICABLE}}
ext{EffectiveScore} = (N_{ ext{IMPLEMENTED}} imes 1.0) + (N_{ ext{PARTIALLY\_IMPLEMENTED}} imes 0.5)
ext{ComplianceScorePct} = ext{round}\left( rac{ ext{EffectiveScore}}{ ext{ApplicableCount}} imes 100.0, 1 ight) \quad ( ext{if ApplicableCount} > 0 ext{ else } 0.0)

Weighting: Implemented controls receive 100% weight ($1.0$), Partially Implemented receive 50% weight ($0.5$), In Progress / Not Started receive 0% weight ($0.0$). Controls marked NOT_APPLICABLE are entirely excluded from both numerator and denominator.

3.2 Phase 3: Evidence Requirement Coverage

Located in backend/app/services/evidence_service.py. Evaluates the ratio of satisfied mandatory evidence requirements:

Evidence Requirement Coverage Formula
ext{CoveragePercentage} = ext{round}\left( rac{|\{r \in \mathcal{R}_{ ext{mandatory}} \mid \exists e \in \mathcal{E}_A(r)\}|}{|\mathcal{R}_{ ext{mandatory}}|} imes 100.0, 1 ight)

Where $\mathcal{R}_{ ext{mandatory}}$ is the set of required evidence requirements, and $\mathcal{E}_A(r)$ is the set of items linked to requirement $r$ with status ACCEPTED. If no mandatory requirements exist, coverage is $100.0\%$ if any accepted item exists, else $0.0\%$.

Deterministic Risk Matrix Engine ($5 imes 5$)

Section 4: Phase 6 — Audit Readiness & Assurance Scoring Engine

Located in backend/app/services/audit_engagement_service.py. Deterministically evaluates whether an audit engagement is prepared for formal review and assurance opinion issuance.

Audit Readiness Score Master Formula
ext{ReadinessScore} = ext{round}\Big(\maxig(0.0, \min(100.0, ( ext{Score}_{ ext{proc}} imes 0.40) + ( ext{Score}_{ ext{evd}} imes 0.30) - P_{ ext{audit}}ig)\Big), 1\Big)

4.1 Constituent Components

1. Procedure Completion Score ($ ext{Score}_{ ext{proc}}$) — Weight: $40\%$

ext{Score}_{ ext{proc}} = egin{cases} \left( rac{N_{ ext{PASSED}} + N_{ ext{PARTIALLY\_PASSED}} + N_{ ext{FAILED}} + N_{ ext{NOT\_APPLICABLE}}}{N_{ ext{total\_procedures}}} imes 100.0 ight) & ext{if } N_{ ext{total\_procedures}} > 0 \ 0.0 & ext{otherwise} \end{cases}

Procedures in NOT_STARTED or IN_PROGRESS do not count as completed.

2. In-Scope Evidence Coverage Score ($ ext{Score}_{ ext{evd}}$) — Weight: $30\%$

ext{Score}_{ ext{evd}} = egin{cases} \left( rac{N_{ ext{controls\_with\_accepted\_evidence}}}{N_{ ext{controls\_in\_scope}}} imes 100.0 ight) & ext{if } N_{ ext{controls\_in\_scope}} > 0 \ 0.0 & ext{otherwise} \end{cases}

3. Unresolved Finding Penalties ($P_{ ext{audit}}$)

P_{ ext{crit\_high}} = \minig((N_{ ext{critical\_findings}} + N_{ ext{high\_findings}}) imes 5.0, \, 20.0ig)
P_{ ext{open}} = \min(N_{ ext{open\_findings}} imes 2.0, \, 10.0)
P_{ ext{audit}} = P_{ ext{crit\_high}} + P_{ ext{open}} \quad ( ext{Maximum Penalty Cap: } 30.0)

4.2 Audit Readiness Bands & Blocker Triggers

Readiness Band Score Range Audit State Implication
READY $[85.0, 100.0]$ Procedures complete, evidence in place, zero high/critical blockers. Ready for opinion issuance.
SUBSTANTIALLY_READY $[60.0, 84.9]$ Minor procedural or evidence gaps remain; remediation on track.
PARTIALLY_READY $[35.0, 59.9]$ Significant gaps in testing procedures or missing evidence on scoped controls.
NOT_READY $[0.0, 34.9]$ Critical unmitigated findings, unperformed procedures, or absent evidence.
Deterministic Readiness Blockers Generated
  • "{N} critical/high finding(s) unresolved": Triggered when $N_{ ext{critical}} + N_{ ext{high}} > 0$.
  • "{N} open finding(s) pending remediation": Triggered when $N_{ ext{open}} > 0 \land (N_{ ext{critical}} + N_{ ext{high}} = 0)$.
  • "No audit procedures defined": Triggered when $N_{ ext{total\_procedures}} = 0$.
  • "{N} procedure(s) not yet started": Triggered when $N_{ ext{NOT\_STARTED}} > 0$.
  • "No controls added to audit scope": Triggered when $N_{ ext{controls\_in\_scope}} = 0$.
  • "{N} in-scope control(s) lack accepted evidence": Triggered when $N_{ ext{controls\_with\_evidence}} < N_{ ext{controls\_in\_scope}}$.

Section 5: Phase 7 — Continuous Control Monitoring (CCM) Health Engine

Located in backend/app/services/monitoring_service.py and specified in PHASE7_CANONICAL_SPEC.md. Evaluates real-time operational health of controls based on live telemetry.

Canonical CCM Health Score Master Formula
ext{RawScore}(c) = ig(E(c) imes 0.35ig) + ig(A(c) imes 0.25ig) + \Big(40.0 - \minig(40.0, \, P_F(c) + P_E(c)ig)\Big)
ext{HealthScore}(c) = ext{round}\Big(\maxig(0.0, \min(100.0, \, ext{RawScore}(c))ig), 1\Big)

5.1 Constituent Metrics & Degradation Curves

1. Evidence Freshness Metric ($E$) — Max Contribution: $35.0 ext{ pts}$

Let $\Delta_{ ext{ev}}$ be the age in days of the latest ACCEPTED evidence item for control $c$, and $ au_{ ext{ev}} = ext{evidence\_max\_age\_days}$ (default 90 days):

E(c) = egin{cases} 0.0 & ext{if no accepted evidence exists} \ 100.0 & ext{if } \Delta_{ ext{ev}} \le au_{ ext{ev}} ext{ (Fresh)} \ ext{round}\left(\max\left(0.0, 1.0 - rac{\Delta_{ ext{ev}} - au_{ ext{ev}}}{ au_{ ext{ev}}} ight) imes 100.0, 1 ight) & ext{if } \Delta_{ ext{ev}} > au_{ ext{ev}} ext{ (Linear Decay)} \end{cases}

Decay Dynamics: Over days $ au_{ ext{ev}} ightarrow 2 au_{ ext{ev}}$ ($90 ext{d} ightarrow 180 ext{d}$), the freshness score decreases linearly from $100.0 ightarrow 0.0$. At day 135 (45 days stale), $E = 50.0$. At $\ge 180$ days, $E = 0.0$.

2. Assessment Currency Metric ($A$) — Max Contribution: $25.0 ext{ pts}$

Evaluates formal control review status and age ($\Delta_{ ext{assess}}$) against $ au_{ ext{assess}} = 180 ext{ days}$:

IMPLEMENTED $\Delta_{ ext{assess}} \le 180 ext{ days}$ (Current) $100.0$ $25.0 ext{ pts}$
IMPLEMENTED $\Delta_{ ext{assess}} > 180 ext{ days}$ (Overdue) $60.0$ $15.0 ext{ pts}$
PARTIALLY_IMPLEMENTED Any Age $50.0$ $12.5 ext{ pts}$
IN_PROGRESS / NEEDS_REVIEW Any Age $25.0$ $6.25 ext{ pts}$
NOT_STARTED / NOT_APPLICABLE Any Age $0.0$ $0.0 ext{ pts}$

Penalties deduct directly from the 40-point baseline credit, capped at a maximum deduction of $40.0$ points:

Section 6: Phase 8 — Multi-Framework Harmonization & Control Rationalization

Located in backend/app/services/harmonization_service.py and specified in PHASE8_ARCHITECTURE.md. Implements the "Assess Once, Comply with Many" cross-regulatory governance engine.

6.1 Rationalized Common Control Inherited Health

Aggregates Phase 7 CCM health scores across all mapped organization controls:

Common Control Inherited Health Formula
ext{InheritedHealth}(CC) = egin{cases} 100.0 & ext{if no mapped controls exist} \ ext{round}\left( \max\left(0.0, \min\left(100.0, rac{\sum_{m \in \mathcal{M}(CC)} w_m \cdot ext{CCMScore}(m)}{\sum_{m \in \mathcal{M}(CC)} w_m} ight) ight), 1 ight) & ext{otherwise} \end{cases}

Weight Constraints: Individual mapping weights $w_m$ are bounded by $w_m \ge 0.1$. The denominator is guarded by $\max(0.1, \sum w_m)$ preventing zero division.

6.2 Subcategory Coverage & Effective Health Classification

Direct vs. Crosswalk Inherited Coverage Rules

1. Direct Coverage Condition:

ext{DirectlyCovered}(s) \iff ext{Status}(s) = ext{IMPLEMENTED} \land ext{CCMHealth}(s) \ge 60.0
ext{EffectiveHealth}_{ ext{direct}}(s) = ext{CCMHealth}(s)

2. Crosswalk Inherited Coverage Condition (Evaluated if not directly covered):

Let $\mathcal{C}(s)$ be the set of crosswalk mappings linking target subcategory $s$ to source subcategory $s_{ ext{src}}$ where $ ext{Confidence}(cw) \ge 0.80$, $ ext{Status}(s_{ ext{src}}) = ext{IMPLEMENTED}$, and $ ext{CCMHealth}(s_{ ext{src}}) \ge 60.0$:

ext{EffectiveHealth}_{ ext{cand}}(cw) = ext{round}ig( ext{CCMHealth}(s_{ ext{src}}) imes ext{Confidence}(cw), \, 1ig)

3. Deterministic Multi-Candidate Resolution:

If multiple crosswalk candidate paths exist for subcategory $s$, the engine selects the candidate with the highest precedence sorted by:

candidates.sort(key=lambda x: (-x[0], -x[1], x[2])) # (-effective_health, -confidence, cw.id)

Deterministic Tie-Breaker: 1st: Highest Effective Health • 2nd: Highest Confidence Score • 3rd: Lowest Crosswalk ID ($cw.id$).

6.3 Framework Coverage & Compliance Score

Framework Posture Master Formulas
ext{CoveragePercentage}(F) = ext{round}\left( rac{|S_{ ext{direct}}(F) \cup S_{ ext{crosswalk}}(F)|}{N_{ ext{total\_subcategories}}(F)} imes 100.0, 1 ight)

Section 9: Fully Worked Numerical Examples

Example 1: Perfect CCM Control Baseline (Score: 100.0 / HEALTHY)

Inputs: Fresh evidence ($20 ext{d} \le 90 ext{d} \implies E = 100.0$), Implemented status assessed $40 ext{d}$ ago ($\le 180 ext{d} \implies A = 100.0$), 0 findings ($P_F = 0$), 0 exceptions ($P_E = 0$).

Calculation:

ext{RawScore} = (100.0 imes 0.35) + (100.0 imes 0.25) + (40.0 - \min(40.0, 0.0)) = 35.0 + 25.0 + 40.0 = 100.0

Result: $\mathbf{100.0}$ • HEALTHY

Example 2: CCM Control with Stale Evidence (135 Days Old)

Inputs: Evidence age $\Delta_{ ext{ev}} = 135 ext{d}$ ($ ext{overage} = 135 - 90 = 45 ext{d}$), Currency $A = 100.0$, Penalties $P_F = 0, P_E = 0$.

Calculation:

E = ext{round}\left( \left(1.0 - rac{45}{90} ight) imes 100.0, 1 ight) = 50.0
ext{RawScore} = (50.0 imes 0.35) + (100.0 imes 0.25) + (40.0 - 0.0) = 17.5 + 25.0 + 40.0 = 82.5

Result: $\mathbf{82.5}$ • HEALTHY

Example 3: CCM Control with SLA-Breached Critical Finding

Inputs: Fresh evidence $E = 100.0$, Current assessment $A = 100.0$, One Critical finding aged $20 ext{ days}$ ($> 15 ext{d} ext{ SLA} \implies P_F = 20.0 + 10.0 = 30.0$).

Calculation:

ext{RawScore} = (100.0 imes 0.35) + (100.0 imes 0.25) + (40.0 - \min(40.0, 30.0)) = 35.0 + 25.0 + 10.0 = 70.0

Result: $\mathbf{70.0}$ • DEGRADED

Example 4: CCM Control with Expired Active Exception and Critical Finding

Inputs: Evidence $E = 100.0$, Currency $A = 100.0$, Critical finding $P_F = 30.0$, Expired Exception $P_E = 15.0$ (Total penalty $= 45.0$).

Calculation:

ext{PenaltyDeduction} = \min(40.0, 30.0 + 15.0) = \min(40.0, 45.0) = 40.0
